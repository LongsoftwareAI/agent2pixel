# Phase 3 — configurable company workflows

User authorized generalized company/task platform, not coding-only. Preserve Habblaud graphics and all existing data. Localhost/single user only. Existing ownership/worktree protocol applies. This is an extensible foundation, not a promise any possible task is executable without tools/credentials.

Backend owner services/api and services/worker except executors/harness; tests/phase3/runtime. Frontend owner apps/web except old office subtree; root owns docs/config/projection; QA tests/phase3 except runtime and own review. Harness owner executors/harness and tests/harness if needed, coordinate first. No concurrent writer per path. Reuse dedicated existing worktrees; update dependencies with cherry-picks, do not reset user changes.

## Contract

GraphNode existing start/agent/condition/end plus agent-node optional `instructions` string max8000 and `deliverable` object `{filename:string}` (safe basename .md/.txt/.json/.csv, max100 chars). Instructions describe task-specific objective/acceptance requirements; same agent may serve multiple distinct nodes. Native/Harness must receive them in assignment text. Existing graph branches remain editable; conditions are explicitly bounded DAG, no unsupported arbitrary-cycle claim.

Node deliverable writes actual final node output, not fixed template, via new catalog tool `artifacts.write_text`. Agent must have grant; review approval occurs AFTER generation, bound to exact filename/content hash/run/agent/node. Persist generated output before interrupt so resume never regenerates or double charges. Denial/expiry/cancel fail closed. Safe artifact directory and exclusive create, max128KiB UTF8, no executable evaluation. Artifact SHA/size/path, provenance source node/agent/run. Payload `{filename,content}`; unsupported extensions/traversal/symlinks rejected. Existing action fixtures compatible. Harness need not request side effects; orchestrator exports actual result after approval; label accurately. Native/Harness use same output-export policy.

GET `/api/workflow-templates` returns `{id,name,description,roles:string[],steps:[{role,instructions,deliverable?:{filename}}]}` array: research brief, content production, operations report, coding review. Frontend maps roles to selected existing workspace agents; never silently change their roles/grants. Instantiates normal editable workflow, safe warning for missing artifact grant. No external send/publish or arbitrary code execution implied. Templates provide guidance, not fabricated research.

GET `/api/work-items?workspace_id=...` -> work items; POST `/api/work-items` fields `{workspace_id,title,description,workflow_id,acceptance_criteria:string[]}`. GET/PATCH `/api/work-items/{id}` optional title/description/criteria only while not active, with validated scope. POST `/api/work-items/{id}/runs` accepts existing RunInput (input optional uses item description+criteria), persists run linkage atomically, one active run per item/workspace rule unchanged. Work item status derived from linked run: backlog/running/waiting_approval/review/failed/cancelled. Completed run => review, never automatically accepted. POST `/api/work-items/{id}/review` `{decision:'accepted'|'changes_requested',comment:string}` only terminal completed latest run; accepted => done, changes_requested => backlog; record reviewer human/time/comment/run. Existing records never mutate from reads. Runs retain work_item_id and brief snapshot. No universal arbitrary company action support claim.

Frontend add Work board navigation and editable brief/criteria/workflow, launch/review and linked evidence. WorkflowEditor add per-node instructions/deliverable and role-mapped templates. Keep all existing screens and flow controls. Screenshot localhost required.

Acceptance: actual multi-role handoffs for research/content/operations using supplied workspace source docs, output exports after exact approval, rejection/no grant/path denial/restart no duplicate output. Provider stubs and deterministic tests explicitly labeled, no fabricated live web research or live model. Independent QA and root review mandatory. No new dependencies needed unless justified. Log ownership/actions/evidence and exact limitations.
